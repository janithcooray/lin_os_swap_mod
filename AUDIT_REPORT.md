# Full Audit Report: lin_os_swap_mod

**Project:** Android 7+ Swapfile Magisk Module
**Author:** janithcooray
**Version audited:** v2.0-c-debug-3 (versionCode 11)
**Audit date:** April 10, 2026

---

## Executive Summary

This is a Magisk module that creates a 4GB or 8GB swap file on Android 7+ devices with configurable swappiness and priority settings. The repo is small and well-structured. No secrets or credentials were found. However, the audit identified **3 high-severity bugs**, **2 medium issues**, and several minor quality improvements.

---

## HIGH Severity

### 1. `rm /data/swap/INCOMPLETE` runs even when fail-safe triggers (service.sh:62)

The fail-safe mechanism is broken. When `/data/swap/INCOMPLETE` exists, the `if/else` block correctly skips swap startup — but the `rm /data/swap/INCOMPLETE` on line 62 is **outside** the if/else block and runs unconditionally. This means the fail-safe flag is always removed on every boot, defeating its purpose entirely. A failed swap start will never actually disable swap on the next boot.

**Fix:** Move `rm /data/swap/INCOMPLETE` inside the `else` block, after the swap starts successfully:

```bash
    fi
    FREE_M="$(free -h)"
    print_log "Free Mem - " $FREE_M
    # Service BOOT OK!
    rm /data/swap/INCOMPLETE
fi
```

### 2. Bash-specific syntax in POSIX shell context (service.sh:49)

The shebang is `#!/system/bin/sh` (POSIX shell), but line 49 uses `[[ "$SWAP_FILE_PRIOR" -eq 0 ]]` which is a Bash-specific construct. On many Android devices, `/system/bin/sh` is `mksh` or `toybox sh`, which may not support `[[ ]]`. This can cause the entire service script to fail silently on some devices.

Additionally, `function` keyword syntax (`function print_log()`) is also a Bash-ism. POSIX only supports `print_log()`.

**Fix:** Replace `[[ ]]` with `[ ]` and remove `function` keywords:

```bash
if [ "$SWAP_FILE_PRIOR" -eq 0 ]; then
```

### 3. Invalid JSON generated by build.sh (build.sh:38)

The JSON update files use single quotes around the version string:

```bash
echo "{\"version\": '$MODFILE_VERSION',\"versionCode\": $MODFILE_VERCODE," > ...
```

This produces `"version": 'v2.0-c-debug-3'` which is **not valid JSON** (JSON requires double quotes). Magisk's update checker may silently fail to parse this, meaning OTA updates won't work.

**Fix:** Use escaped double quotes:

```bash
echo "{\"version\": \"$MODFILE_VERSION\",\"versionCode\": $MODFILE_VERCODE," > ...
```

## MEDIUM Severity

### 4. No disk space check before creating swap file (customize.sh)

The installation script runs `dd if=/dev/zero of=swapfile bs=1048576 count=$SWAP_BIN_SIZE` without first checking available space on `/data`. An 8GB swap file on a device with insufficient space will either fill the partition completely (potentially bricking the device) or fail partway through, leaving a partial file.

**Fix:** Add a space check before `dd`:

```bash
AVAILABLE_MB=$(df /data | tail -1 | awk '{print int($4/1024)}')
if [ "$AVAILABLE_MB" -lt "$((SWAP_BIN_SIZE + 512))" ]; then
    abort "Not enough space on /data. Need ${SWAP_BIN_SIZE}MB, have ${AVAILABLE_MB}MB"
fi
```

### 5. `SWAP_MOD_VERSION` variable referenced but never defined (customize.sh:45)

Line 45 prints `"- Version $SWAP_MOD_VERSION"` but this variable is not set in any vars.sh config file. It's commented out in default.sh.example. Users see a blank version during installation.

**Fix:** Either add `SWAP_MOD_VERSION` to all config files, or source it from `module.prop`.

## LOW Severity

### 6. GitHub Actions uses outdated action versions (release.yml)

`actions/checkout@v2` is several major versions behind. Should be `actions/checkout@v4` for security patches and Node.js 20 compatibility. The current version runs on deprecated Node.js 16.

### 7. Typos in log messages (service.sh:39)

- "sue to fail safe" → "due to fail safe"
- "falied to start" → "failed to start"
- "Remove /data/swap/INCOMPLETE and reboot to disable" — the message says removing the file will "disable" swap, but removing it actually *re-enables* swap. The instruction is inverted.

### 8. Unquoted variables in shell scripts

Multiple instances of unquoted variables that could break with spaces or special characters:

- `service.sh:14` — `if [ -e $1 ]` should be `if [ -e "$1" ]`
- `service.sh:22` — `command -v $1` should be `command -v "$1"`
- `build.sh:24` — `rm -rf $REPO_TOPLEVEL/release` should be quoted
- `build.sh:31` — `cd $REPO_TOPLEVEL` should be quoted

### 9. `cd` without error handling (customize.sh:26,29)

`cd /data/swap && dd ...` — if `/data/swap` doesn't exist (mkdir failed), `dd` runs in the wrong directory. The `&&` helps but `mkdir` failure isn't checked.

### 10. SECURITY.md is stale

Lists v1.0, v1.1, v1.2 as supported but the current version is v2.0. Should be updated.

### 11. Legacy zip symlinks created in repo root (build.sh:55-56)

`cp ... lin_os_swap_mod.zip` and `cp ... swapfile_mod.zip` create files in the repo root directory. These are gitignored but could confuse contributors.

### 12. No `.shellcheck` or linting configuration

Shell scripts would benefit from a ShellCheck CI step — it would catch issues #2 and #8 automatically.

## CI/CD Pipeline Review

The GitHub Actions workflow is simple and functional. Recommendations:

- Upgrade `actions/checkout@v2` → `@v4`
- Pin `softprops/action-gh-release@v2` to a specific SHA for supply chain security
- Add a ShellCheck linting step
- Add JSON validation step for the generated update files
